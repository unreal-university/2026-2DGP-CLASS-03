# LEC09 소닉 애니메이션 뷰어 개발 문서


## 1. 목표와 범위

`PRE-PRD.md`의 요구에 따라 `sonic-sprite.png`에 담긴 소닉의 애니메이션을 자동으로 차례대로 보여 주는 뷰어를 만든다. 각 동작을 5회 재생하고 마지막 화면에서 1초 멈춘 다음 다음 동작으로 넘어간다. 마지막 동작까지 재생하면 첫 동작부터 다시 시작한다.

이번 범위는 자동 재생이다. 키 입력으로 동작을 선택하거나 게임 플레이 기능을 추가하지 않는다. 스프라이트 시트의 제목, 크레딧, 다른 캐릭터 그림처럼 소닉 동작의 프레임이 아닌 영역은 재생 목록에서 제외한다.

## 2. 개발 환경과 산출물

| 항목               | 결정                                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| 언어 및 라이브러리 | Python, pico2d                                                              |
| 작업 위치          | `Labs/LEC09/`                                                             |
| 실행 파일          | `sonic_animation_viewer.py` 한 파일                                       |
| 이미지             | 같은 폴더의`sonic-sprite.png` (399×525 픽셀, RGBA)                       |
| 작업 브랜치        | `feature/animation-viewer`                                                |
| 캔버스             | 1200×800 픽셀                                                               |
| 표시 배율          | 원본 프레임 가로·세로의 4배(초안의 ‘잘 보이도록 확대’를 구체화한 제안값) |

실행은 `Labs/LEC09`에서 `python sonic_animation_viewer.py`로 한다. 파일 경로는 실행 위치에 의존하지 않도록 스크립트 자신의 위치를 기준으로 찾는다. pico2d가 설치되지 않았거나 이미지가 없으면 원인을 알 수 있는 오류를 표시한다. 정상 종료할 때 캔버스를 닫는다.

## 3. 스프라이트 프레임 데이터

강의 자료에서 제시한 목표 목록은 **10개 동작, 총 76프레임**이다. 이 숫자는 구현 전에 실제 이미지와 대조한다. 이미지에 보이는 그림을 행 전체나 동일 크기 격자로 일괄 자르지 않는다. 그림마다 폭과 높이, 간격이 다르므로 각 프레임의 원본 영역을 명시적으로 등록한다.

각 동작 데이터에는 이름, 순서, 프레임 목록을 둔다. 각 프레임에는 이미지 좌측 상단 기준의 `x`, `y`, `width`, `height`와 화면에 그릴 때 발이 놓일 기준점 또는 정렬 오프셋을 둔다. pico2d의 이미지 자르기 좌표는 좌측 하단 기준이므로 `bottom = 이미지 높이 - y - height`로 변환한다. 모든 사각형은 `0 ≤ x`, `0 ≤ y`, `width > 0`, `height > 0`, `x + width ≤ 399`, `y + height ≤ 525`를 만족해야 한다.

프레임 목록을 확정할 때 다음을 기록한다.

1. 10개 동작의 이름과 화면에 나타나는 순서.
2. 동작별 프레임 개수와 합계 76개 여부.
3. 각 프레임의 자르기 좌표와 실제 그림이 잘리지 않는지 여부.
4. 프레임 크기가 달라도 소닉의 발 또는 몸통 기준점이 흔들리지 않는지 여부.

76개와 다른 결과가 나오면 임의로 프레임을 중복하거나 누락하지 않는다. 실제 시트의 분류를 확인하고 이 문서의 목표 수를 먼저 수정한다.

## 4. 기능 요구사항

| ID    | 요구사항                                                           | 완료 기준                                                          |
| ----- | ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| FR-01 | 시작 시 이미지와 프레임 데이터를 불러와 첫 동작부터 자동 재생한다. | 별도 입력 없이 첫 프레임이 표시되고 순서대로 바뀐다.               |
| FR-02 | 모든 등록 동작의 모든 프레임을 원본의 4배 크기로 출력한다.         | 프레임이 잘리거나 다른 행의 그림이 섞이지 않고 화면 안에서 보인다. |
| FR-03 | 한 동작의 프레임 순서를 정확히 5회 반복한다.                       | 한 프레임이 누락되거나 마지막 프레임이 중복 재생되지 않는다.       |
| FR-04 | 5회째 마지막 프레임을 표시한 상태로 1초 정지한다.                  | 정지 동안 프레임과 화면 위치가 유지된다.                           |
| FR-05 | 정지 후 다음 동작의 첫 프레임으로 넘어간다.                        | 등록한 순서대로 한 동작씩 전환한다.                                |
| FR-06 | 마지막 동작의 정지가 끝나면 첫 동작으로 돌아간다.                  | 전체 목록이 종료되지 않고 반복된다.                                |
| FR-07 | 창 닫기 이벤트 또는 Escape 키에 응답해 종료한다.                   | 창이 정상적으로 닫히고 프로세스가 남지 않는다.                     |

프레임 재생 속도의 초기값은 **초당 10프레임**으로 둔다. 실제 시트의 동작을 관찰해 너무 빠르거나 느리면 동작별 속도를 데이터로 지정하고 변경 이유를 기록한다. 재생 시간은 루프 반복 횟수가 아닌 단조 시계의 경과 시간으로 계산한다. 각 프레임은 자신의 표시 시간이 끝날 때까지 보이고, 5회째 마지막 프레임의 표시 시간이 끝난 뒤 1초 정지가 시작된다.

## 5. 화면 및 재생 규칙

- 프레임은 투명 배경을 유지하고 1200×800 캔버스 중앙의 공통 기준점에 그린다. 크기가 다른 프레임도 발 위치가 가능하면 일정해야 한다.
- 매 화면에서 이전 그림을 지우고 현재 프레임을 그린 다음 캔버스를 갱신한다.
- 프레임의 원본 픽셀 크기에 4를 곱해 출력 크기를 계산한다. 시트 전체를 4배로 키우지 않는다.
- 정지 상태에서는 마지막 프레임을 계속 그리되 프레임 인덱스와 동작 인덱스를 바꾸지 않는다.
- 애니메이션과 정지 시간은 실제 경과 시간을 기준으로 처리하여 PC 성능에 따른 속도 차이를 줄인다.

## 6. 단계별 구현 및 커밋 계획

초안의 **최소 20회 커밋** 요구를 충족하도록 기능을 작은 단위로 나누어 구현한다. 각 단계에서 변경한 내용을 실행하거나 검사하고, 확인 가능한 상태를 커밋한다. 커밋 개수만 맞추기 위한 빈 커밋이나 의미 없는 파일 변경은 하지 않는다.

| 단계 | 구현·확인 내용                                                 | 권장 커밋 수 |
| ---- | --------------------------------------------------------------- | -----------: |
| 1    | 실행 진입점, 이미지 경로, 캔버스 열기·닫기, 종료 이벤트        |            3 |
| 2    | 프레임 데이터 구조, 좌표 변환, 경계 검사, 첫 프레임 출력        |            4 |
| 3    | 시트의 동작별 프레임 목록 등록과 이미지 대조                    |            7 |
| 4    | 시간 기반 프레임 전환, 5회 반복, 1초 정지, 다음 동작·전체 순환 |            4 |
| 5    | 4배 출력과 정렬 보정, 실제 창 검증, 문서와 마무리 검사          |       2 이상 |

각 커밋 메시지는 **반드시 한글로 작성**하고 구현한 기능이나 확인한 내용을 드러내야 한다. 예상과 다른 프레임 분류나 배율이 발견되면 문서 수정도 해당 구현 단계에 포함한다.

## 7. 검증 및 완료 기준

1. `sonic_animation_viewer.py`의 문법 검사가 통과하고, `Labs/LEC09`에서 실행해 1200×800 크기의 창이 열린다.
2. 프레임 사각형 전체가 이미지 범위 안에 있으며 동작별 개수 합계가 확정된 목표와 일치한다.
3. 실제 창에서 모든 동작을 한 차례 이상 관찰해 프레임의 잘림, 다른 그림의 혼입, 정렬 튐, 확대 크기를 확인한다.
4. 첫 동작과 마지막 동작을 포함해 각 동작이 5회 반복하고, 5회째 마지막 화면이 약 1초 유지되는지 확인한다.
5. 마지막 동작 다음에 첫 동작이 다시 시작하고 창 닫기와 Escape가 동작한다.
6. `feature/animation-viewer` 브랜치에서 이 작업의 기준 커밋 이후 의미 있는 커밋이 20개 이상인지, 모든 커밋 메시지가 한글인지 로그로 확인한다.

문법 검사만으로 화면의 프레임 자르기나 재생 타이밍이 올바르다고 판단하지 않는다. 위의 이미지 대조와 실제 창 관찰 결과를 함께 남긴다.
